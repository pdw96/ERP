# 감사자

`pdw96/claude-kit@894d5f0` 의 `vibe-audit` 플러그인에서 온 사본이다. 브리핑 커맨드
`/audit-brief` 도 같은 커밋에서 와 `.claude/commands/` 에 있다.

**이 사본이 이 레포의 진실이다.** 원본은 아무 레포에도 안 들어가 본 일반형으로
남아 있어야 하므로, 여기서 고친 것을 그쪽으로 올리지 않는다. 갈리는 것이 정상인
관계다.

체크 항목을 이 레포에 맞게 좁히는 것이 사본을 두는 이유다 — 다만 **첫 감사를
돌린 뒤에** 실제 발견에서 뽑는다. 미리 지어낸 항목은 재지 않고 단정한 것이다.

여섯 다 `tools: ["Read", "Grep", "Glob"]` 이라 고칠 도구가 없다. 그 줄을 지우면
이것들은 감사자가 아니게 된다.

## 바뀐 것을 보이려면 diff 를 같이 줘야 한다

세 도구는 **지금 체크아웃된 파일**만 본다. `git diff` 를 돌릴 수단이 없으므로 PR
번호나 커밋 ID 만 넘기면 기준 커밋과의 차이를 스스로 구하지 못한다.

그래서 과거 상태와의 비교가 필요한 항목 — `audit-contract` 의 필드 삭제 · 이름
변경, `audit-internal` 의 조용히 뒤집힌 결정, `audit-quality` 의 새 코드에 검사가
함께 왔는지 — 은 **부를 때 기준점과 diff 를 본문에 실어 줘야** 판정된다. 안 주면
그 항목들은 「확인불가」이고, 그렇게 적는 것이 맞다.

**diff 는 `/audit-brief <기준> <감사자>` 가 모은다.** 기준 커밋과의 diff · 변경 파일 ·
커밋 범위를 `.claude/audit-brief.md` 에 쓰고 감사자를 부른다. 감사자는 그 브리핑의
「대상」 SHA 를 지금 HEAD 와 견줘, 지난 회차의 것이면 그 diff 로 판정하지 않는다.

**커맨드 사본은 원본과 두 자리가 갈린다**(ERP#13 의 Codex 리뷰). ① 저장소 최상위로
가서 돌고 pathspec 을 `:/` 로 묶는다 — `.` 이면 `backend/` 에서 돌 때 루트의 변경이
빠진다. ② 브리핑과 보관본(`.claude/briefs/`)은 `.gitignore` 에 있다 — 추적 안 된
파일의 본문을 그대로 담아 박힌 키가 커밋될 수 있어서다. 둘 다 원본에도 있는 결함이라
원본이 고치면 다시 받는다.
