# 4단계 스키마 초안 — 재고가 옮겨 가는 길

> **이 문서는 착공(결정 국면)의 산출물인 초안이다.** 어느 것이 섰고 어느 것이
> 아직 초안인지는 아래 표의 마지막 칸이 말한다. 지어진 것의 색인은
> [`schema.md`](schema.md) 다 — 선 표는 그쪽으로 옮겨 가고 여기에는 **초안이 무엇을
> 정했고 지으면서 무엇이 갈렸는지**가 남는다.
>
> **표를 번호로 부르지 않는다** — `schema-3단계.md` 와 같다. 이름으로만 부른다.
>
> 범위는 [`PRD.md`](../PRD.md), 근거는
> [설계도 42판](https://claude.ai/artifact/GMJpbFywKh8wj6N4vEukT6)에 있다. 이름(표 · 칸)은
> 초안의 것이고, 짓는 조각이 고칠 수 있다 — 고치면 이 문서의 상태 칸에 적는다.

## 이 단계가 세우는 것

| 표 | 무엇인가 | 상태 |
|---|---|---|
| `stock_transfer_requests` | 이동 요청 — 어느 로트를 얼마나 옮겨 달라는 의도 | 초안 |
| `stock_transfer_closures` | 요청의 끝 — 처리 또는 취소 가운데 하나 | 초안 |

그리고 **기존 표가 바뀐다** —

| 표 | 무엇이 바뀌는가 | 상태 |
|---|---|---|
| `stock_ledger_entries` | 줄마다 **창고**를 적는다 · `생산출고` · `생산입고` 를 받는다 · 이동 줄은 종결을 근거로 가리킨다 · 잔량 트리거가 **로트 × 창고**로 센다 · 폐기 줄이 재검사 × 창고로 하나 | 초안 |

**`lots` 는 칸이 바뀌지 않는다**(ADR 0022). `warehouse` 는 **들어온 창고**로 뜻이 좁아진다 — 로트가
지금 어디에 얼마 있는지는 원장 줄의 창고별 합이다. 「창고가 담는 품목 유형」 CHECK 는 그대로
옳다(원자재는 원재료창고와 생산창고 둘 다에 설 수 있다). 다만 같은 규칙이 이제 **원장 줄의
창고**에도 걸려야 한다 — 아래.

## `stock_transfer_requests` — 이동 요청

| 칸 | 형 | 비고 |
|---|---|---|
| `id` | PK | |
| `lot_id` | FK → `lots` | 옮길 로트 |
| `quantity` | float | `items.stock_uom` 단위. **`> 0`** 과 `is_finite()` |
| `requested_at` | datetime | |
| `requested_by` | str | 식별 칸. `is_present()` |

**정한 것**

- **요청은 재고를 잡지 않는다** — 요청 수량이 잔량을 넘어도 요청은 선다. 잔량은 처리하는
  순간 원장의 트리거가 본다. 요청은 의도이고 사실이 아니다(원칙 ②)
- **구간 칸을 두지 않는다** — 지금 구간은 원재료창고 → 생산창고 하나뿐이고, 그것은 처리가 내는
  수불유형(`생산출고` · `생산입고`)이 이미 말한다. 둘째 구간(`제품입고`)이 서는 날 구분 칸이
  필요해지는지는 그 단계가 정한다 — 오늘 칸을 두면 값이 하나뿐인 칸을 지어낸다
- **지워지지도 고쳐지지도 않는다** — 원장과 같은 트리거 모양. 잘못 낸 요청은 취소로 거둔다
- **`UNIQUE (id, lot_id, quantity)`** — 행을 좁히지 않는다. **종결이 가리킬 상대**다 — PostgreSQL 은 복합
  외래키가 가리키는 칸 묶음에 그 묶음 그대로의 유일 제약을 요구하고, `id` 의 기본키로는 채워지지 않는다
  (PR #96 Codex 리뷰)

## `stock_transfer_closures` — 요청의 끝

| 칸 | 형 | 비고 |
|---|---|---|
| `id` | PK | |
| `request_id` | FK → `stock_transfer_requests` | **유일** |
| `closure_type` | str | 처리 · 취소 |
| `lot_id` · `quantity` | 요청과 쌍 | 처리 줄이 원장 줄에 같은 로트 · 같은 수량을 넘기는 자리 |
| `closed_at` | datetime | 처리 시각 또는 취소 시각 |
| `closed_by` | str | 처리자 또는 취소자. 식별 칸. `is_present()` |

**정한 것**

- **`UNIQUE (request_id)`** — 요청 하나에 종결 하나. 처리와 취소가 **한 표의 한 칸**이라
  「처리된 요청을 취소」와 「취소된 요청을 처리」가 둘 다 이 유일키에 걸린다(ADR 0023)
- **`FK (request_id, lot_id, quantity) → stock_transfer_requests (id, lot_id, quantity)`** — 종결이
  요청의 로트와 수량을 **쌍으로** 받는다. 처리 수량은 요청 수량과 같다(부분 처리 없음). 세 칸 모두
  `NOT NULL` 이라 복합 외래키가 건너뛰는 자리가 없다
- **`UNIQUE (id, closure_type, lot_id, quantity, closed_at)`** — 행을 좁히지 않는다. **원장 줄이 가리킬
  상대**다
- **취소에는 원장 줄이 없다.** 처리에는 원장 두 줄이 같은 트랜잭션에서 난다 — 「처리 종결은 원장
  두 줄을 가진다」는 다른 표의 줄을 세는 규칙이라 CHECK 로 적을 수 없다. 3단계의 반품 문서가
  원장 줄과 맺은 지연 검사 모양을 따르고, 짓는 조각이 그 장치를 고른다
- **지워지지도 고쳐지지도 않는다**

## `stock_ledger_entries` 가 바뀌는 자리

**더하는 칸**

| 칸 | 형 | 비고 |
|---|---|---|
| `warehouse` | str(20) | `WAREHOUSE`. **`NOT NULL`** — 마이그레이션이 기존 줄을 그 로트의 `lots.warehouse` 로 채운다 |
| `transfer_closure_id` · `transfer_closure_type` | 복합 FK → `stock_transfer_closures` NULL | **이동 줄에서만 찬다** — 그 줄의 근거 문서. 구분 칸은 외래키의 자리이고 차면 처리다 |

**정한 것**

- **받는 유형에 `생산출고` · `생산입고` 를 더한다** — 근거 문서(처리 종결)가 서는 유형만 받는다는
  3단계의 규칙 그대로. `제품입고` 는 받지 않는다 — 근거가 될 이동이 이 단계에 없다
- **유형이 창고를 정한다** — `생산출고` 는 원재료창고, `생산입고` 는 생산창고, 구매입고는 원재료창고.
  폐기출고는 창고를 고르지 않는다(나뉜 로트는 창고마다 한 줄이다). **구매반품출고는 아직 정하지 않았다** —
  `PRD.md` 「착공에서 답을 받지 않은 것」이 든다
- **양방향** — `(txn_type IN ('생산출고', '생산입고')) = (transfer_closure_id IS NOT NULL)`, 그리고
  `(transfer_closure_id IS NULL) = (transfer_closure_type IS NULL)`. 두 조건을 한 식으로 쓰면 구분이 빌 때
  비교가 `NULL` 이 되어 통과한다 — 3단계의 폐기 줄에서 겪은 모양이다
- **차면 처리다** — `transfer_closure_type IS NULL OR transfer_closure_type = '처리'`. 외래키는 원장 줄이 적은
  구분을 **그대로** 종결에서 찾을 뿐이라, 이 CHECK 가 없으면 이동 줄이 `'취소'` 를 적고 취소 종결을 가리켜
  취소된 요청으로 재고를 옮긴다(PR #96 Codex 리뷰)
- **`FK (transfer_closure_id, transfer_closure_type, lot_id, quantity, occurred_at) → stock_transfer_closures`**
  — 이동 줄은 자기 종결을 **처리 · 같은 로트 · 같은 수량 · 같은 시각까지** 가리킨다. 취소 종결을 가리키지
  못하는 것은 위 「차면 처리다」 CHECK 와 이 외래키가 **함께** 막는다
- **부분 유일 인덱스** `(transfer_closure_id, txn_type) WHERE transfer_closure_id IS NOT NULL` — 처리
  하나에 출고 줄 하나 · 입고 줄 하나
- **원장 줄의 창고가 그 품목을 담을 수 있다** — `lots` 의 「창고가 담는 품목 유형」과 같은 규칙이
  원장 줄에도 걸려야 한다. 품목 유형은 로트를 건너야 보이므로 쌍 외래키로 끌어올지 트리거가 볼지는
  짓는 조각이 정한다

**트리거가 바뀌는 자리** — `stock_ledger_entry_keeps_the_balance`(ADR 0013)

- **잔량을 로트 × 창고로 센다.** 한 창고의 합이 0 밑으로 내려가는 줄을 받지 않는다. 로트 줄을 잠그는
  모양(`FOR NO KEY UPDATE`)은 그대로다 — 같은 로트의 두 처리는 창고가 같든 다르든 로트에서 줄을 선다
- **폐기 줄은 그 창고의 잔량 전부다.** 그리고 재검사 하나가 낸 폐기 줄들을 합치면 **로트의 잔량 전부**다 —
  잔량이 남은 창고가 빠지면 받지 않는다. 「모든 창고가 비었는가」는 여러 줄을 함께 보는 규칙이라 줄
  하나가 들어오는 순간에 볼 수 없다 — 지연 트리거로 커밋 때 보는지는 짓는 조각이 정한다
- **폐기 줄의 부분 유일 인덱스** `(retest_id)` 가 **`(retest_id, warehouse)`** 로 바뀐다 — 재검사 하나에
  창고마다 폐기 줄 하나
- **공개 계약이 함께 바뀐다** — 재검사 응답(`RetestOut`)과 서비스 결과는 폐기 줄 id 를 **하나**(`ledger_entry_id`)
  돌려주고, 그 칸은 「잔량 전부가 나갔다」를 확인하는 자리다. 나뉜 로트의 불합격은 줄을 여럿 내므로 그 칸으로는
  다 돌려줄 수 없다. 칸을 목록으로 바꾸면 깨는 변경이고, 목록 칸을 더하고 옛 칸을 남기면 옛 칸이 무엇을
  가리키는지 정해야 한다 — 짓는 조각의 설계 게이트에서 소유자가 정하고 판은 호환 판정이 가른다(ADR 0018 ·
  `PRD.md` 「착공에서 답을 받지 않은 것」, PR #96 Codex 리뷰)

**새 트리거** — 만료된 로트의 처리를 막는다

- 처리 종결이 들어올 때 그 로트의 **지금 만료일**(가장 최근에 합격한 재검사의 갱신 만료일, 없으면
  `lots.expiry_date`)을 현장 시간대의 「오늘」과 견준다. 경계는 재검사 트리거(ADR 0016)와 **같은 경계**를
  쓰고, 둘이 같은지 테스트가 본다
- 요청에는 걸지 않는다 — 요청은 의도이고, 만료는 옮기는 순간의 사실이다

**`lots.warehouse` 를 굳힌다** — 「들어온 창고」로 뜻이 좁아지면 그 칸은 지나간 사실이다. 지금은
원자재 로트의 창고를 원재료창고에서 생산창고로 고쳐도 「창고가 담는 품목 유형」 CHECK 를 지나고, 로트를 지키는
트리거는 수량(`lot_quantity_stays_with_its_ledger`)과 만료일(`lot_expiry_stays_as_labelled`)만 본다. 그러면 로트가
말하는 들어온 창고와 고칠 수 없는 입고 줄의 창고가 갈린다. **원장에 줄이 선 로트의 `warehouse` 를 고치지 못하게**
수량 트리거와 같은 모양으로 막는다(PR #96 Codex 리뷰)

## 마이그레이션이 조이는 자리 — 조이기 전에 묻는다

- **원장 줄의 `warehouse` 를 `NOT NULL` 로 조이기 전에** 기존 줄을 그 로트의 `lots.warehouse` 로 채운다.
  3단계까지의 줄은 모두 원재료창고의 원자재 로트에서 났으므로 채울 수 없는 줄이 없어야 한다 — 그래도
  가드가 먼저 서서, 원재료창고가 아닌 로트에 선 원장 줄이 있으면 무엇을 고칠지 말하고 멈춘다
- **폐기 줄의 유일 인덱스를 넓히는 것**은 받던 줄을 거절하지 않는다 — 가드가 필요 없다
