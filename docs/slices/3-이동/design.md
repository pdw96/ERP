설계다 — **어떻게 · 경계.** 무엇을 · 왜는 같은 폴더의 `requirements.md`.

표 · 칸 · 제약의 모양은 `docs/schema-4단계.md` 의 `stock_transfer_requests` · `stock_transfer_closures` 절과

아래는 그 초안이 「짓는 조각이 정한다」로 남긴 자리와, 짓는 순서다.

## ② 보장하는 것 / 보장하지 않는 것

**보장하는 것**

- 성공 기준의 데이터 쪽은 **데이터베이스가** 지킨다 — 쓰기 경로를 거치지 않고 줄을 넣어도 같은 거절을 받는다.
  쓰기 경로의 거절은 그 앞에 이름을 붙이는 것이다
- 같은 로트의 두 처리는 창고가 같든 다르든 로트 줄의 잠금에서 줄을 선다 — 동시에 와도 잔량이 음수가 되지 않는다(ADR 0013)
- 같은 요청의 처리와 취소가 동시에 오면 종결의 유일키에서 하나가 진다(ADR 0023)
- 나뉜 로트의 재검사 불합격은 커밋 때 로트 잔량이 0 이다 — 창고 하나를 빠뜨린 폐기는 서지 않는다
- 업그레이드는 받던 줄을 조이기 전에 묻는다 — 가드가 멈추면 무엇을 고칠지(로트 번호와 창고)를 말한다

**보장하지 않는 것(알려진 한계)**

- **처리를 기다리는 요청을 셀 수 없다** — 읽는 엔드포인트는 「이동-읽기」의 일이다. 그때까지는 요청 id 를 가진 쪽만 안다
- **같은 요청 본문을 두 번 보내면 요청이 둘 선다** — 요청은 재고를 잡지 않으므로 잔량은 안전하다. 멱등 키는 없다(NC-67 · 226 과
  같은 자리이고, 이 조각이 닫지 않는다)
- **잘못 처리된 이동을 되돌리는 길이 없다** — 처리된 요청은 취소되지 않는다. 반대 방향 이동의 수불유형이 시드에 없다
  (`PRD.md` 「하지 않을 일」 2)
- **반품이 원재료창고의 잔량으로 조여지는 것은 판정 테스트가 보지 못한다** — 거절 이름이 늘지 않는 좁힘이다(ADR 0018 「결정」
  마지막 갈래). 옛 계약 아래에서는 나뉜 로트가 없었으므로 옛 요청이 새로 거절되는 일은 없다 — 리뷰가 이 판단을 본다

## ③ 받는 입력

- **마이그레이션이 받는 것** — 조각 「원장 줄의 창고」까지 선 원장 줄. 유형은 구매입고 · 구매반품출고 · 폐기출고뿐이고, 줄의
  창고는 로트의 들어온 창고다(쓰기 경로가 그렇게 낸다). 그 밖의 줄 — 로트 × 창고 셈에서 음수가 되는 줄, 0 짜리 폐기 줄 — 은
  쓰기 경로가 내지 않지만 제약이 받았으므로, 가드가 세고 멈춘다
- **`POST /stock-transfer-requests`** — 로트 id · 수량 · 요청자. 모르는 칸은 받지 않는다(ADR 0021). 시각은 받지 않고 쓰기
  경로가 「지금」으로 박는다(ADR 0019)
- **`POST /stock-transfer-closures`** — 요청 id · 구분(처리 · 취소, 닫힌 열거) · 처리자 또는 취소자. 로트와 수량은 받지 않는다
  — 요청에서 끌어온다(부분 처리 없음). 시각은 받지 않는다
- **재검사 요청** — 바뀌지 않는다. 바뀌는 것은 응답뿐이다

## ④ 결정

**정한 것**

- 창고는 원장 줄에 적는다 — ADR 0022. 처리와 취소는 종결 표 하나가 가른다 — ADR 0023
- **재검사 응답의 폐기 줄은 목록으로 돌려주고 판을 `2.0` 으로 올린다** — ADR 0025(소유자, 2026-10-19)
- **엔드포인트는 표마다 하나다** — 요청 표에 `POST /stock-transfer-requests`, 종결 표에 `POST /stock-transfer-closures`. 지금의
  `POST /inspections` · `/purchase-returns` · `/retests` 처럼 문서를 세우는 명사형이고, 처리와 취소가 종결 표의 한 칸이라는
  ADR 0023 과 맞는다. 요청 아래에 동사 둘(`/{id}/process` · `/{id}/cancel`)을 두는 모양은 고르지 않았다(소유자, 2026-10-19)
- **취소자는 누구든 된다** — 취소자 칸은 이름을 적을 뿐 요청자와 견주지 않는다(소유자, 2026-10-19)
- **「요청은 로트가 들어온 뒤에만」은 트리거가 본다** — 입고 시각은 원장의 구매입고 줄에만 있고 로트에는 날짜뿐이라, 쌍 외래키로
  끌어올 칸이 없다. 원장 가드가 「들어오기 전의 물건」을 보는 모양을 요청 표에 건다. **입고 줄이 없는 로트에는 요청이 서지 않는다** —
  들어왔다는 사실이 없다
- **「처리 종결은 원장 두 줄을 가진다」는 지연 제약 트리거가 본다** — 반품 문서(`purchase_return_has_its_ledger_line`)와 재검사
  (`retest_failure_has_its_disposal_line`)가 쓰는 모양이다. 종결을 먼저 넣고 줄을 나중에 넣는 순서가 그래서 선다. 줄이 둘을 넘지
  않는 것은 부분 유일 인덱스가 지킨다
- **「나뉜 로트의 폐기는 합쳐서 잔량 전부」는 재검사의 지연 트리거를 넓혀 본다** — 지금 그 트리거는 폐기 줄이 **있는지**만 본다.
  커밋 때 로트의 잔량(모든 창고의 합)이 0 인지까지 보게 넓힌다. 줄 하나하나가 그 창고의 잔량 전부인지는 원장 잔량 트리거가,
  창고마다 하나인지는 `(retest_id, warehouse)` 유일 인덱스가 본다 — 셋이 함께 「잔량이 남은 창고마다 한 줄」을 만든다
- **만료된 로트의 처리를 막는 트리거는 종결 표에 `BEFORE INSERT` 로 건다** — 구분이 처리일 때만. 경계는 재검사 트리거
  (ADR 0016)와 같고, 둘이 같은지 테스트가 본다(`docs/schema-4단계.md` 「새 트리거」)
- **판정은 `ledger_entry_id` 를 지우는 것을 깨는 변경으로 가른다** — B 가 판을 `1.1` 로 둔 채 돌려 「칸이 사라졌다」 ·
  「필수가 풀렸다」로 빨개지는 것을 보았다(`docs/audit/mutations.md` 「이동 PR B」). 이슈 #85 · #93 의 조용한 통과는 이 자리에
  닿지 않았고, 판정을 고치지 않았다
- **짓는 순서는 데이터베이스 → 재검사 → 이동 쓰기 경로다**(⑥). 재검사 경로를 이동보다 먼저 고치는 까닭 — 이동 엔드포인트가 서는
  순간 나뉜 로트가 생기고, 그때 재검사가 로트의 들어온 창고에 폐기 한 줄만 내면 새 트리거에 걸려 500 이 난다

**열어 둔 것**

- **이동 경로의 거절 이름** — 무엇을 이름으로 막을지(모르는 로트 · 원자재가 아닌 로트 · 원재료창고에 남은 것보다 많다 · 만료된
  로트 · 이미 끝난 요청 …)는 C 가 그 PR 을 열기 전에 정하고, 열거는 서비스 파일 한 자리가 든다(ADR 0014). 새 경로의 이름이라
  판정에는 넓히는 변경이다

## ⑤ 검증 계획

- **A — 데이터베이스.** 실제 PostgreSQL 에 붙는 테스트가 성공 기준의 데이터 쪽을 하나씩 본다. 줄을 쓰기 경로 없이 직접 넣어
  거절을 받는다. 동시성(같은 로트의 두 처리 · 같은 요청의 처리와 취소)은 두 연결로 재되, **둘째가 잠금을 기다리는 것을 확인한
  뒤에** 첫째를 커밋한다 — 3단계 조각 1(구매반품)이 남긴 규칙이다(`docs/지나온-길.md`). 「마이그레이션이 모델과 같다」 대조
  (`tests/test_migrations.py`)는 함수 본문과 트리거 정의까지 본다. 가드는 **리비전이 없을 때 빨간 것을 먼저 본다**(조각 「원장
  줄의 창고」가 한 순서)
- **B — 재검사.** 나뉜 로트(직접 넣은 이동 줄)의 불합격이 창고마다 한 줄 · 합이 잔량 전부 · 응답에 id 가 모두 실리는지를 본다.
  판정 테스트(`tests/test_contract_judgment.py`)가 `2.0` 에서 초록, `1.1` 에서 빨강인 것을 본다
- **C — 이동 쓰기 경로.** 요청 → 처리 → 원장 두 줄, 요청 → 취소 → 원장 줄 없음, 그리고 거절 이름마다 한 시험. 트리거가 막는
  것을 경로가 먼저 이름으로 막는지 본다. 반품이 원재료창고의 잔량을 넘으면 `more_than_the_lot_holds` 인 것을 본다
- **어긋냄** — 새 제약 · 트리거 · 가드마다 그것을 걷어 낸 사본에서 해당 시험이 빨갛게 되는 것을 보고 `docs/audit/mutations.md` 에
  남긴다. 각 PR 이 자기 몫을 든다. 보장 → 시험 → 어긋냄의 대응은 그 PR 본문이 든다
- **판정 분기 커버리지 하한**(ADR 0024)은 B 에서 그대로 문다 — 판정을 고치면 그 분기도 판정 테스트가 돌려야 한다
