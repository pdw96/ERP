# 조각 4 — 이동-읽기 (2026-10-21 착공)

요구사항이다 — **무엇을 · 왜.** 어떻게 · 경계는 같은 폴더의 `design.md`, 대안이 있던 결정은 ADR.

## 문제

조각 「이동」이 로트를 원재료창고에서 생산창고로 옮기는 줄을 세웠지만, **옮긴 결과를 읽을 길이 없다.** 로트를 읽는
응답의 `balance` 는 모든 창고의 합이라, 로트 A 가 원재료창고 30 · 생산창고 20 이어도 밖에서는 50 하나만 보인다.
생산창고에 무엇이 투입을 기다리는지 셀 수 없다는 `PRD.md` 「문제」가 쓰는 쪽에서는 그대로다. 처리를 기다리는 요청도
요청 id 를 쥔 쪽만 안다 — 자재 담당에게 할 일 목록이 없다.

닫힌 조각 「이동」이 이 조각으로 넘긴 것이 셋이다(`docs/slices/3-이동/requirements.md` 「닫으며」).

- **같은 이동 요청을 두 번 보내면 요청이 둘 서고 둘 다 처리될 수 있다**(NC-230, 보통). 감사 ㊹ 때 실제로 돌린 장부 —
  로트 500 에 「100 옮겨 줘」가 응답이 끊겨 두 번 들어가고 둘 다 처리되면 원재료 300 · 생산 200 이 남는다. 실제로 옮긴 것은
  100 이다. 처리된 이동은 되돌릴 길이 없다(`PRD.md` 「하지 않을 일」 2)
- **반품의 거절 이름과 `balance` 의 뜻이 스펙에 없다**(감사 ㊺ OB-1). 구매 쪽이 `balance: 500` 을 읽고 400 을 반품하면
  `more_than_the_lot_holds` 로 거절된다 — 그 이름은 원재료창고의 잔량(300)을 넘었다는 뜻인데, 밖에서 읽을 수 있는 수는 합뿐이다
- **종결을 재시도하면 원장 줄 id 를 되찾을 길이 없다**(감사 ㊹ 가 `audit-contract` 로 넘긴 것) — 이 조각의 그 담당 회차가 본다

## 핵심 사용자와 시나리오

- 사용자: 자재 담당 처리자. 계정은 없다(`CLAUDE.md` 「판정자는 칸이고 표가 아니다」)
- 시나리오: 생산 쪽이 로트 A(원재료창고 500)의 100 을 옮겨 달라는 요청에 번호표를 붙여 낸다 → 응답이 끊겨 같은 번호표로
  다시 보낸다 → 요청은 하나뿐이고, 둘째 응답은 첫째와 같은 요청 id 를 돌려준다 → 자재 담당이 처리를 기다리는 요청 목록을
  읽는다 — 그 요청 하나가 로트 번호 · 수량 · 요청자와 함께 보인다 → 처리한다 → 목록에서 사라진다 → 로트 A 를 읽으면
  합계 `balance` 500 과 창고별로 원재료 400 · 생산 100 이 보인다 → 생산창고에 잔량이 있는 로트만 거른 목록에 로트 A 가 있다

## 성공 기준

- **`PRD.md` 성공 기준 9 가 이 조각의 것이다** — 창고별 잔량은 저장하지 않고 읽는 엔드포인트가 원장의 합에서 구하며,
  응답이 바뀌는 만큼 판이 움직이는지는 호환 판정이 가른다. 여기에 옮겨 적지 않는다
- **로트를 읽으면 창고별 잔량이 함께 온다** — `GET /lots/{lot_id}` 와 `GET /lots` 의 로트 한 줄마다. 창고별 잔량을 합하면
  `balance` 와 같다
- **로트 목록을 창고로 거른다** — 「그 창고에 잔량이 있는 로트만」. 재검사를 기다리는 로트 거름과 함께 쓸 수 있고, 넘기는
  도중의 커서는 거름이 다르면 이름으로 거절된다(ADR 0020)
- **처리를 기다리는 요청을 목록으로 읽는다** — 종결(처리 · 취소)이 없는 요청만, 요청 하나마다 요청 id · 로트 · 로트 번호 ·
  품목 · 수량 · 요청자 · 요청 시각. 처리하거나 취소하면 다음 읽기에서 빠진다
- **이동 요청에 번호표(멱등 키)를 붙일 수 있다** — 같은 번호표가 다시 오면 새 요청이 서지 않고 첫 요청의 id 를 돌려준다.
  첫 요청이 이미 처리 · 취소됐어도 같다. 같은 번호표가 다른 내용(로트 · 수량 · 요청자)으로 오면 이름 있는 거절이다. 같은
  번호표의 두 요청이 **동시에** 와도 요청은 하나다 — 데이터베이스의 유일 제약이 지킨다. 번호표 없이 보내면 지금처럼 받는다
- **스펙이 두 수의 뜻을 말한다** — `balance` 는 모든 창고의 합이고, 반품의 `more_than_the_lot_holds` 는 원재료창고의 잔량을
  넘었다는 뜻이다(감사 ㊺ OB-1)
- **판은 넓힘만큼 움직인다** — 판정 테스트가 이 조각의 변경을 모두 넓히는 변경으로 가르고, 판의 앞자리는 `2` 로 남는다
- **새 검사마다 어긋내서 빨갛게 되는 것을 본다** — 기록은 `docs/audit/mutations.md`

## 하지 않을 일

1. **요청 하나를 읽는 엔드포인트를 세우지 않는다** — 처리를 기다리는 목록만 선다(저장소 소유자, 2026-10-21). 그래서 종결을
   재시도한 쪽이 원장 줄 id 를 되찾는 길도 이 조각에 서지 않는다 — 설계 ② 「보장하지 않는 것」
2. **처리됐거나 취소된 요청을 읽는 목록을 세우지 않는다** — 목록은 처리를 기다리는 요청뿐이다. 다만 그런 목록을 나중에
   더해도 깨지지 않는 모양으로 둔다(설계 ④)
3. **번호표를 반드시 붙이게 하지 않는다** — 붙이지 않은 요청은 지금처럼 받는다(저장소 소유자, 2026-10-21). 판이 `3.0` 이
   되는 깨는 변경을 고르지 않았다
4. **종결(처리 · 취소)에 번호표를 두지 않는다** — 종결은 요청 하나에 하나라 유일키가 이미 두 번 서는 것을 막는다(ADR 0023)
5. **창고 × 품목 합계(현황표)를 세우지 않는다** — 로트 단위로 읽고 거른다(저장소 소유자, 2026-10-21)
6. **`PRD.md` 「하지 않을 일」이 그대로 선다** — 원재료창고 → 생산창고 밖의 이동 · 부분 처리 · 재고를 잡는 요청 · 사용자 표 ·
   상쇄 경로 · 화면 · 배포. 여기에 옮겨 적지 않는다

## 제약

- **스택과 비용**: `PRD.md` 「제약」 그대로 — 새 의존성 없음 · 로컬 Docker Compose · 월 0원
- **스키마 변경은 마이그레이션과 함께**, 리비전을 낸 뒤 `tests/test_migrations.py` 를 돌린다(`CLAUDE.md` 「금지」) — 번호표 칸이
  요청 표에 선다. 앵커볼트(데이터 모델)를 건드리고, 소유자가 착공에서 골랐다
- **공개 계약은 넓히기만 한다** — 기존 경로의 응답에 이름이 늘면 `docs/openapi-declarations.json` 에 가른다. 깨는 변경이 나오면
  짓기 전에 소유자에게 묻는다
- **리뷰 한도**: `docs/리뷰-루프.md` 가 정한다 — 점수 · 쏠림 신호 · 소유자에게 묻는 문턱
- **닫기 전에 감사 회차** — 스키마가 움직이고 NC-230 의 기한이 이 조각이므로 `audit-data`, 공개 계약이 넓어지고 ㊹ · ㊺ 가 넘긴
  자리가 이 조각이므로 `audit-contract`
