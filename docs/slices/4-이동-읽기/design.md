## ② 보장하는 것 / 보장하지 않는 것

**보장하는 것**

- **같은 번호표의 요청은 하나다** — 데이터베이스의 유일 제약이 지킨다. 쓰기 경로를 거치지 않고 줄을 넣어도 둘째는 서지 않는다
- **같은 번호표의 두 요청이 동시에 와도** 요청은 하나이고, 둘 다 같은 요청 id 를 받는다 — 진 쪽이 500 을 받지 않는다
- **같은 번호표 · 같은 내용**(로트 · 수량 · 요청자)이면 첫 요청과 같은 상태 코드 · 같은 본문이다. 첫 요청이 처리 · 취소된
  뒤에도 같다. **다른 내용**이면 이름 있는 거절이고 아무 줄도 서지 않는다
- 번호표 없이 보낸 요청은 이 조각 전과 똑같이 받는다
- **창고별 잔량을 합하면 `balance` 다** — 둘은 같은 원장 줄을 같은 셈(유형의 `total_effect`)으로 센다(ADR 0013)
- **창고 거름은 그 창고에 잔량이 있는 로트만** 돌려준다. 재검사를 기다리는 거름과 함께 쓰면 둘 다 채운 로트다. 넘기는 동안
  조건을 계속 채운 줄은 겹치지도 빠지지도 않는다(ADR 0020)
- **처리를 기다리는 목록은 종결이 없는 요청만**이다 — 처리 · 취소가 커밋된 뒤의 읽기에는 나오지 않는다
- 이 조각의 변경은 모두 **넓히는 변경**이고, 판정 테스트가 그렇게 가른다 — 판의 앞자리는 `2` 다

**보장하지 않는 것(알려진 한계)**

- **번호표 없이 보낸 요청은 여전히 둘 설 수 있다** — 번호표는 고르는 칸이다(ADR 0027). 처리를 기다리는 목록이 둘을 함께
  보이는 것이 그쪽에 남은 그물이다
- **번호표를 유일하게 짓는 것은 부르는 쪽이다** — 서버는 번호표의 글자를 해석하지 않는다. 두 부르는 쪽이 같은 번호표를 지으면
  둘째는 내용이 같을 때 첫 요청을 받고, 다를 때 거절된다
- **종결을 다시 보낸 쪽은 원장 줄 id 를 되찾지 못한다** — 둘째는 `request_is_already_processed` 를 받는다. 요청 하나를 읽는
  엔드포인트를 세우지 않았다(요구사항 「하지 않을 일」 1). 감사 ㊹ 가 넘긴 자리이고 이 조각의 `audit-contract` 회차가 판정한다
- **목록은 읽는 순간의 답이다** — 잠그지 않는다. 읽은 뒤 처리하기 전에 다른 사람이 처리 · 취소하면 처리하는 쪽이 이름 있는
  거절로 안다
- **처리를 기다리는 요청이 처리될 수 있는지는 목록이 말하지 않는다** — 잔량 · 만료는 처리하는 순간 본다(`PRD.md`
  「하지 않을 일」 4). 목록은 요청이 적은 것만 돌려준다
- **반품의 거절 이름은 바뀌지 않는다** — `more_than_the_lot_holds` 의 뜻을 스펙 산문이 말할 뿐이다. 이름을 바꾸면 판이 `3.0` 이다
- **창고 거름은 잔량이 0 이 된 창고를 보이지 않는다** — 그 창고를 거쳐 간 로트를 찾는 길은 아니다

## ③ 받는 입력

- **마이그레이션이 받는 것** — 조각 「이동」까지 선 요청 줄. 번호표 칸이 없다. 새 칸은 비어서 서고 조일 것이 없어 가드가 없다.
  요청 줄을 고치지도 지우지도 못하게 하는 트리거(`stock_transfer_request_comes_after_the_receipt` — 넣기 · 고치기 · 지우기에
  함께 걸린다)는 새 칸에도 그대로 걸린다
- **`POST /stock-transfer-requests`** — 로트 id · 수량 · 요청자에 **번호표**(고르는 칸, 글자)가 더해진다. 모르는 칸은 여전히
  받지 않는다(ADR 0021). 번호표의 경계(길이 · `is_present()`)는 ④ 가 연다
- **`GET /lots/{lot_id}`** — 바뀌지 않는다. 바뀌는 것은 응답이다
- **`GET /lots`** — 지금의 `awaiting_retest` · `limit` · `cursor` 에 **창고**(고르는 인자, `codes.WAREHOUSES` 의 닫힌 목록)가
  더해진다. 커서는 이 목록이 내준 것만 받는다 — 이 조각 전에 내준 커서는 「창고 거름 없음」으로 읽는다
- **처리를 기다리는 요청의 목록** — `limit` · `cursor`. 경로의 모양은 ④ 가 연다

## ④ 결정

**정한 것**

- **번호표는 골라 붙이고, 같은 번호표 · 같은 내용이면 첫 요청을 돌려준다** — ADR 0027(소유자, 2026-10-21)
- **로트를 읽으면 창고별 잔량이 오고, 로트 목록을 창고로 거른다** — 창고 × 품목 합계(현황표)는 세우지 않는다(소유자, 2026-10-21)
- **처리를 기다리는 요청은 목록만 읽는다** — 요청 하나 읽기 · 처리됐거나 취소된 요청의 목록은 세우지 않는다(소유자, 2026-10-21).
  착공에서 낸 추천은 요청 하나 읽기까지였다 — 감사 ㊹ 가 넘긴 종결 재시도의 자리를 닫는 길이었다
- **창고별 잔량은 `{창고, 잔량}` 의 목록이다** — 잔량이 있는(0 보다 큰) 창고만, `codes.WAREHOUSES` 순서로 싣는다. 합이
  `balance` 이고, 창고가 늘어도 칸의 모양이 그대로다. 창고 이름은 열린 문자열이다(`x-known-values`)
- **번호표가 견주는 내용은 로트 · 수량 · 요청자다** — 요청 시각은 서버가 적는 값이라 견주지 않는다
- **같은 번호표의 재시도는 같은 상태 코드 · 같은 본문이다** — 다시 보낸 쪽이 처음 받았어야 할 답을 받는다. 「이미 있었다」를
  따로 알리지 않는다
- **번호표 칸은 비어 있을 수 있고 유일 제약은 채워진 줄끼리만 견준다** — PostgreSQL 의 유일 제약은 `NULL` 끼리 견주지 않는다.
  옛 줄의 빈 번호표를 지어내지 않는다
- **처리를 기다리는 목록은 요청 id 순서다**(ADR 0020) — 먼저 낸 요청이 먼저 온다. 한 줄은 요청 id · 로트 id · 로트 번호 ·
  품목 코드 · 수량 · 요청자 · 요청 시각이다
- **커서는 `app/api/cursor.py` 하나가 든다** — 목록마다 한 벌씩 짓지 않는다(ADR 0020). 다른 목록 · 다른 거름의 커서는 지금의
  `cursor_is_for_another_list` 로 거절한다
- **이동 표의 `lot_id` 인덱스를 두지 않는다** — 이 조각의 쿼리는 그 칸으로 찾지 않는다. 처리를 기다리는 목록은 종결의 요청
  유일키로 거르고 요청 대리키로 넘기며, 창고별 잔량은 원장의 `lot_id` 인덱스를 쓴다. `docs/schema.md` 「미룬 것」의 기한을
  「그 칸으로 찾는 쿼리가 서는 조각」으로 고친다(C)
- **짓는 순서는 번호표 → 창고별 잔량 → 처리를 기다리는 목록이다**(⑥). 번호표를 목록보다 먼저 세우는 까닭 — 목록이 서는
  순간 같은 요청 둘이 처음 남에게 보이는데(대장 NC-230 의 기한), 그때는 막는 길이 이미 서 있어야 한다

**열어 둔 것**

- **번호표가 다른 내용으로 왔을 때의 거절 이름과 번호표의 경계(길이 상한)** — A 가 열기 전에 정하고 저장소 소유자가 확인한다
  (조각 「이동」의 거절 이름과 같은 길)
- **창고 거름이 `GET /lots` 에 새 거절 이름을 내는가** — 쿼리 인자는 옛 서버가 무시하고 받았으므로 넓힘의 근거가 못 된다
  (감사 NC-227). 기존 경로에 새 이름이 나가면 깨는 변경이다. B 가 열기 전에 새 이름이 나가지 않는 모양을 고르거나, 고를 수
  없으면 짓기 전에 소유자에게 묻는다
- **처리를 기다리는 목록의 경로 모양** — 나중에 처리됐거나 취소된 요청의 목록을 더해도 이 경로의 뜻이 바뀌지 않는 모양이어야
  한다. C 가 열기 전에 정한다

## ⑤ 검증 계획

- **A — 번호표.** 실제 PostgreSQL 에 붙는 시험이 ② 의 번호표 조건마다 하나 이상 본다 — 같은 번호표의 줄을 쓰기 경로 없이
  넣어 유일 제약에 걸리는 것, 같은 내용의 재시도가 같은 id 를 받고 요청 표의 줄 수가 늘지 않는 것, 첫 요청이 처리 · 취소된 뒤의
  재시도, 다른 내용의 거절, 번호표 없는 요청 둘. 동시성은 두 연결로 재되 **둘째가 잠금을 기다리는 것을 확인한 뒤에** 첫째를
  커밋한다(`docs/지나온-길.md` 3단계 조각 1). `tests/test_migrations.py` 의 대조가 리비전과 모델을 견준다. 감사 ㊹ 의 장부(로트
  500 에 같은 100 요청 둘)를 번호표를 붙여 다시 돌려 원재료 400 · 생산 100 이 남는 것을 PR 본문에 장부 모양으로 싣는다
- **B — 창고별 잔량.** 나뉜 로트 · 한 창고뿐인 로트 · 잔량 0 인 로트에서 창고별 잔량과 그 합 = `balance` 를 본다. 창고 거름은
  그 창고에 잔량이 있는 로트만 · 재검사 거름과 함께 · 거름이 다른 커서의 거절 · 이 조각 전에 내준 커서가 계속 읽히는 것을 본다
- **C — 처리를 기다리는 목록.** 요청 → 목록에 있음 → 처리 → 없음, 요청 → 취소 → 없음, 순서와 넘김(겹치지도 빠지지도 않음),
  다른 목록의 커서 거절을 본다
- **판정** — 각 PR 에서 `tests/test_contract_judgment.py` 가 넓히는 변경으로 가르고, 판의 뒷자리를 올리지 않은 사본에서
  빨개지는 것을 본다. 판정 분기 커버리지 하한(ADR 0024)은 그대로 문다
- **시험 규칙** — 한 갈래의 시험이 다 지는 것이다.
  - 거절 시험은 `detail[].type` 의 이름과, 요청 표 · 원장의 줄 수가 그대로인 것을 본다
  - 성공 시험은 응답 본문과 표의 줄 수를 본다
  - ② 의 보장 조건마다 꼴이 하나 이상 있다
  - 새 제약 · 분기마다 그것을 걷어 낸 사본에서 해당 시험이 빨갛게 되는 것을 보고 `docs/audit/mutations.md` 에 남긴다

  보장의 조건 → 꼴 → 어긋냄의 대응은 각 PR 본문이 든다
