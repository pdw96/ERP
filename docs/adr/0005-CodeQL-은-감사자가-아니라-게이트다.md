# ADR 0005 — CodeQL 은 감사자가 아니라 게이트다 — 워크플로 파일로 둔다

- 상태: 채택
- 날짜: 2026-09-29
- 정한 사람: 저장소 소유자

## 맥락

이 저장소는 공개라 GitHub 의 code scanning(CodeQL)을 비용 없이 쓸 수 있다. CodeQL 은 입력이
흘러가는 길을 따라가 로그 주입 · 민감값 기록 · 에러 응답의 내부 노출 같은 부류를 본다. 감사
⑲ 의 NC-173(판정자 전원이 서버 로그로)과 NC-174(경로가 로그 줄의 모양을 정함)가 **사람의
회차를 기다려** 난 바로 그 부류다. 워크플로 파일(`actions`)도 본다.

그런데 이 저장소는 이미 자기 규칙이 있다.

- **잡아도 머지를 막지 못하면 잡은 것이 아니다**(NC-101).
- **목록을 두 벌 두지 않는다** — 부적합은 대장 하나에 산다.
- **파일 밖 설정은 리뷰도 감사도 닿지 않는다** — `audit-quality` 항목 1 이 룰셋을 「확인불가」로
  적는 까닭이다.

## 대안

- **가) 켜지 않는다.** 감사자의 회차만 남는다.
- **나) 설정 화면의 default setup.** 가장 가볍다. 대신 설정이 저장소에 보이지 않는다.
- **다) 워크플로 파일(advanced setup)로 두고, 감사자가 아니라 게이트로 다룬다.**

## 결정

**다).**

- `.github/workflows/codeql.yml` — `python` · `actions` 를 빌드 없이 본다. PR · `main` 푸시 ·
  매주 한 번(질의가 늘어나므로). 결과를 올리는 권한(`security-events: write`)은 그 잡에만 준다.
- **알림은 대장으로 옮기지 않는다.** PR 안에서 고치거나, GitHub 에서 사유를 적어 기각한다.
  리뷰 루프의 점수에도 넣지 않는다 — 게이트의 빨강은 CI 의 빨강과 같다.
- **머지를 막는 것은 룰셋이다.** 저장소 설정의 룰셋에 「Require code scanning results」를
  더한다 — 이 파일 밖이라 저장소 소유자가 건다. 걸어 둔 기준(2026-09-29):
  - **Security alerts — Medium or higher.** 기본값(High)보다 한 단계 낮다. 이 게이트를 세운
    부류(로그 주입 · 민감값 기록)는 대개 High 지만, 에러 응답의 내부 노출처럼 Medium 으로 나오는
    부류도 감사가 실제로 다뤄 왔다. 세운 날 막히는 알림이 0 건이라 비용이 없었다.
  - **Alerts — Errors.** 기본값. 기본 질의 묶음은 보안 질의가 중심이라 보안이 아닌 알림이 적다.
  - Low · Note 는 막지 않는다 — 목록에서 보고 따로 다룬다.

## 결과

- **default setup 과 함께 켤 수 없다.** 설정 화면에서 default setup 이 켜져 있으면 이 파일의
  결과가 받아지지 않는다 — 꺼 둔다.
- **이 게이트가 못 보는 것** — 정해진 질의에 없는 부류. 권한 설계 · 업무 규칙 · 스키마 제약처럼
  코드의 흐름이 아니라 뜻을 봐야 하는 것은 여전히 감사자의 자리다.
- **룰셋의 기준은 파일로 확인할 수 없다.** 위의 값은 이 ADR 이 적은 것일 뿐이고, 설정에서
  바뀌어도 아무것도 빨개지지 않는다(`audit-quality` 항목 1 의 그 빈자리).
- **매주 스캔이 `main` 에서 새로 낸 알림은 아무것도 막지 않는다.** 질의가 늘어 옛 코드에서 새
  알림이 나오면, 그것을 막을 PR 이 없다. Security 탭에 쌓일 뿐이고 알려 주는 것도 없다 —
  사람이 탭을 본다.
