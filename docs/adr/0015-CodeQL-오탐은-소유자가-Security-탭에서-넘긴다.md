# ADR 0015 — CodeQL 오탐은 소유자가 Security 탭에서 넘긴다

- 상태: 채택
- 날짜: 2026-10-02
- 정한 사람: 저장소 소유자(2026-10-02, PR #71 머지 뒤 인터뷰)

## 맥락

ADR 0005 가 CodeQL 을 게이트로 세웠다 — 룰셋의 code scanning 규칙이 medium 이상 경고로 머지를 막는다.
PR #71(3단계 조각 2)에서 처음으로 그 게이트가 물었다. 반품 라우트가 거절 예외를 `str(refused)` 로 응답에
싣는 것을 CodeQL 이 예외 정보 노출(`py/stack-trace-exposure`, medium)로 읽었다.

**실리는 것은 스택 트레이스가 아니라 우리가 지어 넘긴 거절 문장이라 내용상 오탐이었다.** 경고를 넘기는
권한(dismiss)이 그 세션에 없어(경고 목록부터 403), 저자는 같은 글자를 `refused.message` 로 싣도록
코드를 바꿨고(`951c6a6`) 경고가 사라져 머지됐다. 보내는 글자는 한 자도 바뀌지 않았다 — **노출을 막은
것이 아니라 감지기가 흐름을 알아보지 못하게 한 것**이고, 오탐이라는 판단은 커밋 메시지와 주석에만 남았다.

그리고 CodeQL check run 은 경고가 있어도 「success」로 끝나 경고가 출력 안에만 있었다 — CI 가 전부
초록인데 PR 이 `blocked` 였고, 원인은 머지를 시도해서야 드러났다.

## 대안

- **가) 코드로 넘긴다.** 같은 내용을 감지기가 읽지 못하는 식으로 다시 쓴다. 빠르고 권한이 필요 없다.
  그러나 **판정이 사람 없이 사라진다** — 오탐이라는 판단이 틀렸으면 진짜 경고를 숨긴 것이 되고, 그것을
  가를 기록이 GitHub 에 없다
- **나) 소유자가 Security 탭에서 「False positive」로 넘긴다.** 누가 · 왜 넘겼는지가 경고에 남고, 코드는
  감지기를 속이는 모양을 갖지 않는다. 대가는 소유자의 손 한 번이다
- **다) 그때그때 정한다.** 규칙이 없으면 오늘처럼 권한이 없는 쪽이 가)를 고른다

## 결정

**나).** CodeQL 이 머지를 막았는데 오탐으로 보이면, 작업하는 쪽(사람이든 세션이든)은 **코드로 넘기지
않는다.** 경고의 위치 · 규칙 · 오탐이라고 보는 근거 · dismiss 사유 문안을 정리해 소유자에게 보고하고
멈춘다. 넘기는 것은 소유자가 Security 탭에서 한다. 진짜 경고면 고친다 — 그때의 고침은 **보내는 것을
바꾸는** 고침이어야 한다.

**`951c6a6` 은 이 결정 앞의 판정이라 되돌리지 않는다**(「규칙은 소급하지 않는다」, `docs/audit/README.md`).
보내는 글자가 같고, 그 고침이 반품 라우트의 메시지를 무는 검사를 더했다. `app.py` 의 그 자리 주석이 이 ADR 을
가리킨다.

## 결과

- 오탐의 판정이 GitHub 의 경고 기록에 남는다. 감지기를 속이는 코드가 새로 생기지 않는다
- 「CI 초록인데 `blocked`」는 CodeQL check run 의 출력부터 본다 — `CHECKLIST.md` 「항상」이 든다
- **이 결정이 덮지 않는 것** — 거절 메시지가 다른 검사의 판정 · 사유 · 수량 · 로트 번호를 싣는 것(감사 ㊱ 이
  `audit-secrets` 로 넘겼다)은 스택 트레이스 경고와 다른 질문이다. 기한은 그대로 「읽는 엔드포인트가 서는
  조각」(먼저 오면 배포처가 서는 조각)이다
