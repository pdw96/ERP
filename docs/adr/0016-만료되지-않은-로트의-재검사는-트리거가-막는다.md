# ADR 0016 — 만료되지 않은 로트의 재검사는 트리거가 막는다

- 상태: 채택
- 날짜: 2026-10-02
- 정한 사람: 저장소 소유자(3단계 재검사 조각의 설계 게이트)

## 맥락

3단계의 재검사는 만료된 로트의 일이다 — 「만료되지 않은 로트는 재검사를 받지 않는다」
(`docs/schema-3단계.md` 「`inspections` 가 바뀌는 자리 — 재검사」). 그런데 「만료」는 재검사 줄
하나만 보고 가를 수 없다. 로트의 **지금** 만료일은 「가장 최근에 합격한 재검사의 갱신 만료일,
없으면 `lots.expiry_date`」이고, 그것을 판정 시각과 견줘야 한다 — **다른 표의 여러 줄**을 보는
조건이라 CHECK 로 적을 수 없다. 초안은 이것을 쓰기 경로와 트리거 가운데 어디서 막을지 「지으면서
정한다」로 미뤄 두었다.

`CLAUDE.md` 「금지」는 적어 두기만 하고 강제하지 않는 규칙을 막고, CHECK 로 적을 수 없는 규칙은
트리거가 건다고 적는다(ADR 0013).

## 대안

- **가) 트리거가 막고, 쓰기 경로가 먼저 이름으로 막는다.** `inspections` 에 재검사 줄이 들어올 때
  트리거가 가리키는 로트의 지금 만료일을 구해 판정 시각과 견준다. 쓰기 경로는 같은 조건을 먼저 물어
  업무 거절의 이름으로 돌려준다 — 조각 2 가 잔량에 쓴 모양이다(「트리거가 막는 것을 쓰기 경로가
  먼저 이름으로 막는다」)
- **나) 쓰기 경로만.** 단순하지만 지키는 것이 코드 한 곳이다. NC-70 이 낸 상태 — 「오늘 갈리지
  않는 것은 쓰는 코드가 하나뿐이라서이며 그것은 제약이 아니라 우연이다」 — 를 이 자리에 다시 만든다

## 결정

**가).**

- 트리거는 가리키는 로트 줄을 잠그고 지금 만료일을 구한다 — 같은 로트에 두 재검사가 동시에 오면
  둘 다 「아직 만료」를 보고 함께 서므로, 잔량 트리거(ADR 0013)처럼 로트 줄에서 줄을 세운다.
  잠금의 세기는 ADR 0013 이 겪은 교착(`KEY SHARE` 와의 충돌)을 보고 짓는 자리에서 정한다
- 견줌의 경계(만료일 당일이 만료인가)는 짓는 자리에서 정해 `docs/schema-3단계.md` 에 적는다 —
  트리거와 쓰기 경로가 **같은 경계**를 쓰는지 테스트가 본다
- 쓰기 경로의 거절 이름은 ADR 0014 의 열거에 더한다

### 트리거가 지킬 것 — 짓는 자리로 미루지 않는다

PR #75 의 Codex 리뷰가 낸 셋이다. 셋 다 이 조건을 그대로 SQL 로 옮기면 생기는 구멍이라, 짓기 전에
요건으로 적는다. 각각 트리거와 쓰기 경로 양쪽의 테스트가 문다.

- **지금 만료일이 없으면(NULL) 만료가 아니다 — 거절한다.** `shelf_life_days` 가 NULL 이면 무기한이고
  (`docs/schema.md`), 입고는 그 로트의 `expiry_date` 를 NULL 로 세운다(`app/services/incoming.py`).
  SQL 에서 NULL 과의 견줌은 참도 거짓도 아닌 NULL 이라, 「만료되지 않았으면 막는다」를 그대로 적으면
  **만료되지 않는 로트가 재검사를 통과한다.** NULL 분기를 따로 둔다
- **지금 만료일은 들어오는 줄을 빼고 구한다 — `BEFORE INSERT` 다.** 합격한 재검사는 자기 갱신
  만료일을 든다. `AFTER INSERT` 로 「가장 최근 합격 재검사」를 물으면 방금 넣은 그 줄이 잡혀 로트가
  아직 만료되지 않은 것으로 보이고, **정상인 합격 재검사가 전부 거절된다.** 합격 재검사가 서는 성공
  경로 테스트가 이 시점을 문다
- **UPDATE 로 비켜 가지 않는다.** 검사 줄은 반품이 가리킬 때만 고정된다(`inspection_stays_behind_its_returns`).
  그 밖에서는 재검사 줄의 가리키는 로트 · 판정 시각을 고쳐 만료되지 않은 로트로 옮길 수 있고, 앞선
  합격 재검사의 갱신 만료일을 고쳐 뒤의 재검사를 소급해 무효로 만들 수 있다. **재검사 줄을 고정하거나,
  그 칸들이 바뀔 때 같은 검사를 로트 잠금과 함께 다시 돌린다.** 고정이 단순하다 — 판정 기록을 고칠
  정당한 경로가 아직 없고, 다시 돌리면 뒤의 재검사까지 따라 물어야 한다. 어느 쪽인지는 짓는 자리에서
  정하되, UPDATE 경로를 무는 테스트가 함께 선다

## 결과

- 재검사를 내는 길이 몇 개가 되든 「만료 로트만」 규칙은 한 자리에 산다
- **모델에 보이지 않는 규칙이 하나 더 는다.** ADR 0013 의 결과와 같다 — 트리거의 정의를 따로
  견주고, 트리거를 지우거나 조건을 뒤집으면 빨갛게 되는 것을 본다(`docs/audit/mutations.md`)
- 같은 조건이 트리거와 쓰기 경로 두 자리에 적힌다. 「목록을 두 벌 두지 않는다」의 예외가 아니다 —
  강제하는 것은 트리거 한 자리이고 쓰기 경로는 이름을 주려고 먼저 묻는 것이며, 둘이 갈리면 트리거가
  이긴다(이름 없는 거절이 난다). 갈리는 것은 위의 경계 테스트가 문다
- 트리거가 못 보는 부류는 ADR 0013 과 같다 — 트리거를 끄고 넣는 길은 권한의 일이다
