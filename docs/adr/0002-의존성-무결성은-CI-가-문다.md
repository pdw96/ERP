# ADR 0002 — 감사 ⑳ 이 넘긴 의존성 무결성과 토큰 권한은 CI 가 문다

- 상태: 채택
- 날짜: 2026-09-29
- 정한 사람: 저장소 소유자

## 맥락

감사 ⑳(`audit-secrets`)이 담당 없는 둘을 넘겼다.

- **의존성 무결성** — 개발 의존성이 진짜 패키지 · 실재 버전인가. 여섯 감사자 누구의 체크
  항목에도 없었다(⑧ 의 UNK-2 에 이어 둘째). 실재를 확인하려면 외부 조회가 필요한데, 감사자의
  도구(Read · Grep · Glob)로는 할 수 없다.
- **`ci.yml` 에 `permissions:` 가 없다** — `GITHUB_TOKEN` 의 권한이 저장소 설정의 기본값을
  따라 파일 밖에서 정해졌다.

그리고 설치는 직접 의존성만 고정했다. 하위 의존성은 설치하는 날마다 달리 왔고, 실제로
starlette 가 그렇게 와서 CI 만 떨어진 적이 있다(`backend/requirements.in` 머리).

## 대안

- **가) 감사자에게 맡긴다** — `audit-secrets` 의 체크 항목에 더한다. 도구로 할 수 없는 확인이
  남고, 회차 사이에 들어온 의존성은 다음 회차까지 아무도 보지 않는다.
- **나) CI 가 문다.** 파일로 적을 수 있는 것은 파일로 적고, 매 PR 이 검사한다.

## 결정

**나).**

- 토큰은 `ci.yml` 의 `permissions: contents: read` 로 좁힌다.
- 의존성은 하위 의존성까지 버전과 해시로 잠그고(pip-tools), CI 와 이미지가 잠금에서
  `--require-hashes` 로 설치한다. 잠금이 입력에서 다시 나오는지는 CI 가 본다 — 어떻게
  보는지는 ADR 0004 가 정한다.

## 결과

- 같은 이름 · 같은 버전으로 다른 파일이 오면 설치가 멈춘다. 검사가 도는 환경과 이미지가 같은
  버전을 쓴다.
- **해시가 못 닫는 것이 남는다** — 처음부터 엉뚱한 패키지를 고른 것(타이포스쿼팅). 해시는
  처음 받은 파일을 충실히 잠글 뿐이다. 의존성을 더하는 날 사람이 이름과 출처를 본다.
- **값이 따른다** — 하위 의존성의 보안 패치가 저절로 들어오지 않는다. 그 빈자리는 ADR 0003
  이 메운다.
