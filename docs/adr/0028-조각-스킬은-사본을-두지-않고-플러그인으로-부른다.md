# ADR 0028 — 조각 스킬은 사본을 두지 않고 플러그인으로 부른다

- 상태: 채택
- 날짜: 2026-11-02
- 정한 사람: 저장소 소유자가 물었다(「계정 플러그인으로 도는데 사본이 필요한가」). 스킬과 감사자를 가르는 선은 맡겨서 정했다

## 맥락

`slice-docs` · `slice-review` 는 claude-kit 의 `vibe-slice` 플러그인에서 `.claude/skills/` 로 베껴 왔다. 그때는 이 레포에서
부를 길이 사본뿐이었다. 사본은 원본이 바뀔 때마다 다시 심었다(`4e07b01` · `21bb6ab` · `0320581`).

이제 같은 플러그인이 계정에 등록돼 세션마다 `vibe-slice:` 로 뜬다. 사본(`ee9f58f`)과 플러그인(`2e60e97`)을 견주니 **이 레포만의
고침이 한 줄도 없었다** — 다른 것은 출처 커밋을 적은 머리 주석, 절차 지도 링크의 커밋, 그리고 사본이 아직 받지 못한 원본의 새
것(대장 검사 `verify-ledger.py` · 대장 틀 둘 · 요구사항 틀의 「감사 회차」 줄)뿐이었다. 사본은 특화가 아니라 **늦은 원본**이었다.

감사자 여섯(`.claude/agents/`)과 `/audit-brief`(`.claude/commands/`)는 다르다. 이 레포의 대장 경로 · `UNK-n` 번호 · 낮음을 이슈로 보내는
규칙(ADR 0011) · Alembic 의 DDL 잠금 표(대장 「사본 특화 대기」 W-1 · W-4 · W-8)를 들고 있다.

## 대안

- **가) 스킬 사본을 걷고 플러그인으로 부른다. 감사자 사본은 둔다.** 갈래를 실제 차이로 가른다
- **나) 둘 다 걷는다.** 감사자의 특화를 잃는다 — 다음 회차가 대장을 못 잇는다
- **다) 둘 다 둔다.** 스킬 사본은 다시 심기 전까지 원본보다 늦고, 두 벌이 갈린다(`CLAUDE.md` 「목록을 두 벌 두지 않는다」).
  지금도 늦어서 대장 검사가 빠져 있었다

## 결정

**가).** 조각 스킬은 `vibe-slice:slice-docs` · `vibe-slice:slice-review` 로 부른다. 이 레포에 사본을 두지 않는다. 감사자와
`/audit-brief` 는 지금처럼 이 레포의 사본을 스코프 없는 이름으로 부른다.

## 결과

- 스킬의 판은 **이 레포의 커밋이 아니라 계정의 플러그인이 정한다.** 원본이 바뀌면 다시 심지 않아도 다음 세션부터 바뀐다.
  어느 판으로 썼는지는 스킬이 가리키는 절차 지도 링크의 커밋이 든다
- 플러그인이 없는 세션에서는 조각 스킬을 부를 수 없다 — 계정에 플러그인을 켜는 것이 고침이다
- 스킬 사본의 리뷰 지적을 가르던 규칙(`docs/리뷰-루프.md`, PR #102)은 대상이 없어졌다. 플러그인의 결함은 이 레포의 PR 에
  오지 않으므로 claude-kit 에서 다룬다
- 감사자 사본에 이 레포만의 고침이 남지 않는 날이 오면 같은 물음을 감사자에게 다시 묻는다
