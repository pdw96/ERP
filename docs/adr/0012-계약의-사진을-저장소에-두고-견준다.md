# ADR 0012 — 계약의 사진을 저장소에 두고 견준다

- 상태: 채택
- 날짜: 2026-10-01
- 정한 사람: 저장소 소유자

## 맥락

`/openapi.json` 은 다음 층이 코드를 만드는 **기계가 읽는 계약**인데(`README.md`), 실행할 때 지어져 저장소에 없었다.
그래서 오류 이름(`Transport` · `Refusal`)이나 응답 선언을 바꾸는 PR 에서 리뷰어가 보는 것은 `schemas.py` 의 한 줄이었고,
**밖으로 나가는 계약이 어떻게 바뀌는지**는 어떤 diff 에도 없었다. 이름을 검사하는 테스트는 양변이 같은 원천이라 이름을
더하거나 바꿔도 초록이었다 — 어긋내 확인했다(`mutations.md` 의 `1e0a336` 160 줄). 감사 ⑯ 과 ㉛ 이 같은 자리를 관찰로
두 번 냈다(OB-1).

API 코드는 약 열흘 동안 커밋 열둘이 건드렸고, 받던 요청을 거절하게 된 변경이 셋 있었다(NC-102 · 103 · 115). 동시에
읽는 엔드포인트가 서기 전까지 **계약을 좁히는 것은 자유롭다**(`app.py` 머리, NC-136 · 158) — 그 창이 닫히는 조각이
언제인지는 `PRD.md` 어디에도 적혀 있지 않다.

## 대안

- **가) 미룬다.** 닫는 조건을 「읽는 엔드포인트가 서는 조각」에 묶어 적기만 한다. 기준선은 그날 옛 커밋에서 다시 지을 수
  있으므로 잃는 것은 기준이 아니라 **창이 열린 동안 PR 마다 보이는 것**이다. 그런데 그날이 정해져 있지 않다
- **나) 지금 사진을 둔다.** `docs/openapi.json` 을 커밋하고 테스트가 실제 스펙과 견준다. 계약을 바꾸면 사진을 다시 지어야
  초록이 되어 그 diff 가 리뷰에 남는다. 막지는 않는다
- **다) 지금 호환성 판정까지 세운다.** 깨는 변경과 넓히는 변경을 가른다. 창이 열린 동안 깨는 변경은 허용되므로 지금 세우면
  허용된 것을 매번 막거나 예외로 넘기는 검사 — 통과하면서 아무것도 지키지 않는 검사 — 가 된다

## 결정

**나).** 다)의 판정은 읽는 엔드포인트가 서는 조각이 세운다 — 그날 판 이동 규칙(깨지면 앞자리, 넓어지면 뒷자리)이 함께
서고, 그 조각은 반드시 `app.py` 를 고치므로 조건이 스스로 드러난다.

- 사진은 `docs/openapi.json`, 짓는 것은 `backend/app/api/spec.py`(`render()` 한 자리 — 테스트와 같은 함수를 쓴다)
- 다시 짓는다: `cd backend && .venv/bin/python -m app.api.spec`
- 키를 정렬해 선언 순서가 아니라 계약이 바뀔 때만 diff 가 난다

## 결과

- `test_the_spec_matches_the_snapshot_in_the_repository` 가 견준다. `http_error` 를 `path_error` 로 고치는 것과 열거에
  `ghost` 를 더하는 것 — 전에 초록이던 둘 — 이 이제 빨갛다(`mutations.md` 의 「ADR 0012」 묶음)
- **선언 밖으로 나가는 응답은 못 본다** — 선언이 없으니 사진에도 없다(NC-220 의 400). 그것은 응답을 실제로 일으켜 견주는
  검사가 맡는다
- **생각 없이 다시 지은 사진도 못 막는다** — 이 결정은 보이게 하는 것이지 막는 것이 아니다. 보는 것은 리뷰다
- 계약을 바꾸는 커밋마다 명령 하나가 더 든다. 그 마찰이 「계약을 바꾸고 있다」는 신호다
