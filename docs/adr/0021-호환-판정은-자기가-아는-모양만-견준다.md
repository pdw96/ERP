# ADR 0021 — 호환 판정은 자기가 아는 모양만 견준다

- 상태: 채택
- 날짜: 2026-10-03
- 정한 사람: 저장소 소유자(PR #84 Codex 리뷰 2 라운드 뒤의 쏠림 신호)

## 맥락

ADR 0018 의 판정 테스트는 두 스펙을 견주어 깨는 변경과 넓히는 변경을 가른다(`app/api/compat.py`). 처음 지은 판정은
OpenAPI 를 손으로 흉내 냈다. PR #84 Codex 리뷰가 두 라운드에 열한 건을 냈고, 그중 열 건이 이 모듈에 있었다.
1 라운드는 넷이었다 — `security`, `operationId`, `$ref` 옆 제약, 그리고 모듈 밖의 로컬 기준 한 건.
2 라운드는 일곱이었다.

- 요청 미디어 타입의 `encoding`
- Path Item 의 `$ref`
- 이름이 바뀐 재귀 스키마
- `oneOf` 의 겹치는 갈래
- `True == 1`
- 포함 · 배제 경계의 쌍
- `additionalProperties` 를 연 요청 객체

모두 이 PR 의 새 경로에서 재현되는 실결함이었다. 1 라운드에 「따로 가르지 않는 칸은 통째로 견준다」로 고쳤는데,
2 라운드는 그 옆에서 다시 났다. `docs/리뷰-루프.md` 의 쏠림 신호다 — 고칠 때마다 새 틈이 난다.

이 저장소의 스펙은 FastAPI 가 짓는 한 파일이다. 지적의 모양은 어느 것도 그 파일에 없었다.

## 대안

- **A. 관리되는 구현(`oasdiff`)으로 바꾼다.** 이것이 깨는 변경을 판정하고, 이름 선언(`x-known-values`)만 우리 코드에 남긴다.
  - Go 바이너리라 개발 의존성이 하나 늘고, 로컬 `pytest` 에도 그 바이너리가 든다.
  - 깨는 변경의 목록이 ADR 0018 의 것에서 그 도구의 것으로 바뀐다(응답의 경계를 조이는 것 등)
- **B. 입력을 계약으로 좁힌다.** 판정이 아는 모양을 닫힌 목록으로 두고, 그 밖의 모양이 옛 계약이나 새 계약에 나오면
  견주지 않고 빨갛게 한다. 목록 안에 남는 지적(경계의 쌍 · JSON 의 같음 · 열린 요청 객체)만 코드로 고친다.
  - 지금 스펙에서 걸리는 자리는 없다.
  - 대가 — 사람이 지킬 작성 규칙이 하나 생긴다
- **E. 후속으로 뗀다.** 알려진 틈과 함께 머지한다. 조용한 통과가 남는다

## 결정

**B.** 저장소 소유자가 골랐다(2026-10-03).

- 판정이 아는 모양은 `app/api/compat.py` 의 「판정이 아는 모양」 한 자리가 든다. 이 ADR 에 베끼지 않는다
- **새 모양을 쓰려면 판정부터 넓힌다.** 목록에 더하고, 그 모양의 변화를 가르는 코드와 어긋내 빨개지는 검사를 같은 PR 에
  함께 낸다
- 요청이 받는 객체는 모르는 칸을 받지 않아야 한다(`additionalProperties: false`). 그래야 옛 스키마에 없던 칸이 「받지 않던
  입력」이 되어 이름 선언의 근거가 될 수 있다
- 1 라운드의 「나머지 칸 통째 비교」는 걷어 냈다 — 모르는 칸은 이제 견주는 대신 거절된다

## 결과

- 판정의 크기가 이 저장소가 쓰는 모양에 묶인다. 모양이 넓어지는 날 판정의 일도 함께 는다 — 그 마찰이 이 결정이 사는 것이다
- 판정이 견주지 못하는 모양이 조용히 지나가지 않는다 — `test_a_shape_the_judgment_does_not_know_is_refused`
- 목록 안의 의미를 다 가르지는 못한다 — 판정 테스트의 독스트링이 그 부류를 든다(W-6 ③)
