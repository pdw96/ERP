# ADR 0018 — 계약은 읽는 엔드포인트와 함께 1.0 으로 닫는다

- 상태: 채택 — 서는 날은 3단계의 읽는 엔드포인트 조각이다
- 날짜: 2026-10-03
- 정한 사람: 저장소 소유자(3단계 읽는 조각의 설계 인터뷰)

## 맥락

ADR 0012 는 계약의 사진을 두되 **호환 판정**(깨는 변경과 넓히는 변경을 가르는 것)은 「읽는 엔드포인트가 서는 조각이
세운다」고 미뤘다. 그때까지 판은 `0.1` 로 고정되고 계약을 좁히는 것은 자유롭다(`app/api/app.py` 의 `API_VERSION` 주석).
3단계의 쓰기 조각(반품 · 재검사)이 모두 머지되어 남은 조각이 바로 그 읽는 조각이다.

미룬 것을 세우려면 셋을 정해야 했다 — 창을 이 조각에서 닫는가, 닫으면 판은 무엇이 되는가, 그리고 **응답에 실리는
열거에 값을 더하는 것**을 어느 쪽으로 세는가. 마지막 것은 이 저장소에서 흔하다 — 업무 거절의 이름(ADR 0014)이
조각마다 늘었고, 늘 때마다 그 열거가 응답의 `detail[].type` 에 실린다.

## 대안

창과 판 —

- **가) 창을 닫고 `1.0` 으로 올린다.** 판정 테스트가 서고, 그 뒤로 깨는 변경은 앞자리를 올려야 초록이다
- **나) 판정만 세우고 `0.x` 를 유지한다.** semver 의 0.x 관례대로 깨는 변경도 뒷자리 이동으로 받는다. 붙은 클라이언트가
  없는 동안 좁힐 자유를 더 오래 쥔다. 대신 창이 반쯤 열린 채로 남아 「언제 닫히는가」가 다시 정해지지 않은 기한이 된다
  (NC-158 이 이미 한 번 낸 모양이다)
- **다) 다시 미룬다.** 닫는 조건을 첫 배포 같은 다른 사건에 묶는다

응답 열거의 추가 —

- **ㄱ) 닫힌 열거 그대로 두고 넓히는 변경(뒷자리)으로 센다.** 스펙이 「응답의 열거는 늘 수 있다」를 적는다. 처음 고른
  것이었는데 **약속이 지켜지지 않는다**(PR #80 Codex 리뷰) — 옛 스펙의 `enum` 으로 코드를 생성하거나 응답을 검증하는
  클라이언트는 새 값이 오면 응답 자체를 거부하고, 새 스펙의 설명은 이미 배포된 클라이언트를 바꾸지 못한다
- **ㄴ) 깨는 변경(앞자리)으로 센다.** 분기를 닫아 둔 클라이언트까지 지키지만, 거절 이름 하나마다 판이 2.0 · 3.0 으로 오른다
- **ㄷ) 응답에 실리는 이름을 열린 문자열로 싣는다.** 스펙은 닫힌 `enum` 대신 「알려진 값」의 목록을 함께 든 문자열로 적는다.
  값을 더하는 것이 정말로 넓히는 변경이 된다. 대가 — 생성된 클라이언트가 응답의 이름을 타입으로 받지 못한다

## 결정

**가)와 ㄷ).** 처음에는 가)와 ㄱ)이었고, PR #80 의 Codex 리뷰가 ㄱ)의 약속이 지켜지지 않음을 짚어 저장소 소유자가 ㄷ)으로
바꿨다(2026-10-03).

- 읽는 엔드포인트가 서는 PR 이 `API_VERSION` 을 `1.0` 으로 올리고, `app.py` 의 「창이 열려 있다」 산문을 지금의 규칙으로
  바꾼다
- **판정은 기준 브랜치의 사진과 이 브랜치의 사진을 견주는 테스트가 한다.** ADR 0012 의 대조(실제 스펙 = 이 브랜치의
  사진)는 그대로 두고, 판정은 그 옆에 따로 선다 — 계약을 바꾸는 PR 은 사진을 다시 지으므로 실제 스펙과 사진은 언제나 같고,
  둘만 견주면 견줄 옛 계약이 없다(PR #80 Codex 리뷰). **기준은 기준 브랜치와 갈라진 커밋(merge-base)의
  `docs/openapi.json`** 이다. 깨는 변경이면 앞자리가, 넓히는 변경이면 뒷자리가 기준의 판보다 커야 초록이다. 기준을 읽을
  수 없으면(얕은 체크아웃 따위) 건너뛰지 않고 실패한다 — CI 의 체크아웃이 그 커밋을 받아야 한다. 무엇이 깨는 변경인지는
  그 테스트의 독스트링 한 자리에 적는다 — 이 ADR 에 목록을 베끼지 않는다(`CLAUDE.md` 「목록을 두 벌 두지 않는다」)
- **요청이 받는 이름은 닫힌 열거다** — 값을 더하면 넓히는 변경, 빼거나 이름을 바꾸면 깨는 변경이다
- **응답이 내는 이름은 열린 문자열이다** — 업무 거절의 이름(`detail[].type`)과 판정(`result`) 같은 자리다. 알려진 값의
  목록은 스펙에 함께 싣되 닫힌 `enum` 으로 적지 않는다. 그래서 값을 더하는 것은 넓히는 변경이다. **같은 뜻을 다른
  이름으로 내기 시작하는 것**(이름 바꾸기)은 그 이름에 분기한 부르는 쪽을 깨므로 깨는 변경이다
- 코드 안에서는 그대로 열거다 — ADR 0014 의 「경로마다 열거 하나」는 바뀌지 않는다. 바뀌는 것은 그 열거를 스펙에 싣는
  모양뿐이고, 읽는 엔드포인트 조각이 기존 경로의 응답 이름까지 함께 옮긴다(창이 닫히기 전이라 판은 그 PR 의 `1.0` 에 든다)

## 결과

- 창이 닫히기 전에 내고 싶은 좁히는 변경은 그 PR 앞에 낸다 — 이슈 #73(꺼진 사유 코드)을 읽는 조각보다 먼저 따로 내는
  까닭이다(저장소 소유자가 정했다, 2026-10-03)
- 판정 테스트도 새 검사이므로 어긋내서 빨개지는 것을 본다(`docs/audit/mutations.md`)
- **선언 밖의 응답은 여전히 못 본다** — ADR 0012 의 결과 그대로다
- 붙은 클라이언트가 아직 없는데도 깨는 변경의 비용이 오른다. 그 비용이 이 결정이 사는 것이다 — 「좁혀도 되는 창」이
  기한 없이 남는 것을 끝낸다
