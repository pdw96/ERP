# ADR 0027 — 이동 요청의 번호표는 골라 붙인다

- 상태: 채택 — 서는 날은 4단계 조각 「이동-읽기」의 번호표 PR 이다
- 날짜: 2026-10-21
- 정한 사람: 저장소 소유자(조각 「이동-읽기」 착공 인터뷰)

## 맥락

같은 이동 요청을 두 번 보내면 요청이 둘 서고, 원재료창고에 두 배가 있으면 둘 다 처리된다(감사 ㊹ NC-230). 실제로 돌린
장부 — 로트 500 에 「100 옮겨 줘」가 응답이 끊겨 두 번 들어가고 둘 다 처리되면 원재료 300 · 생산 200 이 남는다. 실제로
옮긴 것은 100 이다. 처리된 이동은 반대 방향 수불유형이 없어 되돌릴 길이 없다(`PRD.md` 「하지 않을 일」 2).

요청은 재고를 잡지 않는 의도라(원칙 ②) 같은 로트 · 같은 수량의 요청이 둘인 것이 그 자체로 틀린 것은 아니다 — 같은 양을
정말 두 번 옮겨 달라고 할 수 있다. 「다시 보낸 것」과 「새로 낸 것」을 가르는 것은 보내는 쪽만 안다. 대장은 이 자리의 기한을
처리를 기다리는 요청이 처음 읽히는 조각 「이동-읽기」로 정했다(저장소 소유자, 2026-10-21).

## 대안

- **가) 번호표(멱등 키)를 골라 붙인다.** 요청에 번호표 칸을 두고 유일 제약을 건다. 같은 번호표가 다시 오면 새 요청을 세우지
  않고 첫 요청을 돌려준다. 번호표 없이 보낸 요청은 지금처럼 받는다. 요청 본문에 필수 아닌 칸이 서는 넓힘이라 판은 `2.x` 다
- **나) 번호표를 반드시 붙인다.** 없으면 거절한다. 요청에 필수 칸이 서는 깨는 변경이라 판이 `3.0` 이다. 응답이 끊겨 다시
  보내는 쪽이 번호표를 빠뜨릴 길이 없다
- **다) 막지 않는다.** 처리를 기다리는 목록에 둘 다 보이니 자재 담당이 보고 하나를 취소한다. 스키마는 그대로다. 사람이 보지
  못하고 둘 다 처리하면 되돌릴 길이 없다
- **라) 같은 로트 · 같은 수량의 처리 전 요청이 있으면 거절한다.** 보내는 쪽은 바뀌지 않는다. 같은 양을 정말 두 번 요청하는
  일도 함께 막힌다 — 제약이 일어날 수 있는 사실을 막는다

## 결정

**가).** 저장소 소유자가 골랐다(2026-10-21). 착공에서 낸 추천은 나)였다 — 번호표를 고를 수 있으면 다시 보내는 쪽이
번호표를 빠뜨렸을 때 그대로 둘이 선다.

- 번호표는 **부르는 쪽이 짓는다.** 서버는 적고 견줄 뿐이다
- 번호표는 요청 표의 칸이고 **유일 제약이 지킨다** — 같은 번호표의 두 요청이 동시에 와도 요청은 하나다
- 같은 번호표가 **같은 내용**(로트 · 수량 · 요청자)으로 오면 첫 요청을 돌려준다 — 첫 요청이 이미 처리 · 취소됐어도 같다
- 같은 번호표가 **다른 내용**으로 오면 이름 있는 거절이다 — 다른 요청을 첫 요청으로 돌려주면 보내는 쪽은 자기 요청이 섰다고
  믿는다
- 번호표는 지우지 않는다 — 요청 줄을 고치지도 지우지도 않으므로(원칙 ⑦) 번호표도 그 줄과 함께 영원히 남는다

## 결과

- 번호표를 붙이는 부르는 쪽은 응답이 끊겨도 안전하게 다시 보낸다. **붙이지 않는 쪽은 NC-230 의 자리에 그대로 있다** —
  계약이 그것을 강제하지 않는다. 처리를 기다리는 목록이 같은 요청 둘을 보이는 것이 그쪽의 남은 그물이다
- 번호표를 반드시 붙이게 바꾸는 날은 깨는 변경이다 — 그날 판의 앞자리가 오른다
- 요청 표에 칸이 하나 선다. 옛 요청 줄은 번호표가 비어 있다 — 없는 값을 지어내지 않는다
